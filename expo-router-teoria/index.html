    ¿Qué significa “navegar” en una app?

    En la web

    ‹ › tienda.com/productos/3
    Chipá (docena)
    • Cada página tiene una URL visible.
    • El navegador guarda un historial: atrás y adelante.
    • Un link lleva a otra URL.

    En el celular

    /
    /productos
    /productos/3
    • No hay barra de direcciones.
    • Las pantallas se apilan una encima de otra.
    • Se vuelve con un gesto o el botón atrás de Android.
    • Tabs y menús laterales cambian de sección.
    La idea clave Expo Router une los dos mundos: cada pantalla del celular también tiene una URL.

    Preguntar: ¿qué pasa cuando tocan "atrás" en WhatsApp dentro de un chat? ¿Y en Instagram al cambiar de pestaña? Dejar que noten la diferencia entre apilar y cambiar de sección.

    ¿Qué es Expo Router?

    Es el sistema de navegación de Expo. Las carpetas y archivos de src/app se convierten en las pantallas y rutas de tu app. Por dentro usa React Navigation, que en SDK 57 ya viene incluido en el paquete.

    Rutas por archivos

    Creás perfil.tsx y ya existe la pantalla /perfil. No hay que registrar nada.

    Deep links automáticos

    Cualquier pantalla se puede abrir desde un link externo, una notificación o un QR.

    Android, iOS y web

    El mismo código navega en las tres plataformas; en web las URLs son reales.

    La pila · LIFO

    Last In, First Out: el último elemento que entra es el primero que sale. Solo se trabaja por un extremo, llamado tope.

    • push(x) apila un elemento en el tope.
    • pop() saca y devuelve el del tope.
    • tope() mira el de arriba sin sacarlo (también peek).
    • vacia indica si no queda nada.

    Pensalo como la pila de parciales para corregir: el último que dejaron arriba es el primero que agarrás.

    › pila = [A, B, C]

    Hacer push un par de veces y preguntar antes de cada pop: "¿cuál va a salir?".

    La cola · FIFO

    First In, First Out: el primero que llega es el primero que sale. Se agrega por el final y se saca por el frente.

    • encolar(x) agrega al final (enqueue).
    • desencolar() saca el del frente (dequeue).
    • frente() mira quién sigue sin sacarlo.

    Es la fila del comedor: nadie se cuela, se atiende en orden de llegada.

    ← sale (frente)entra (final) ←
    › cola = [Ana, Beto, Caro]

    Contrastar con la pila: con los mismos datos de entrada, sale otro elemento. La estructura define el comportamiento.

    Pila vs cola, lado a lado

    Pila (stack)Cola (queue)
    OrdenLIFO: último en entrar, primero en salirFIFO: primero en entrar, primero en salir
    Entra porel topeel final
    Sale porel tope (el mismo extremo)el frente (el extremo opuesto)
    En JavaScriptarray.push() + array.pop()array.push() + array.shift()
    Vida realCtrl+Z, pila de platos, historial del navegadorfila del banco, cola de impresión, mensajes por enviar
    En una app móvilel historial de pantallas de un Stackacciones de navegación esperando ejecutarse
    Truco para recordar Pila = platos (se sacan de arriba). Cola = fila (se atiende al primero).

    La última fila de la tabla es el puente al tema de la clase: la próxima diapositiva lo muestra con código real.

    Implementarlas en JavaScript

    p.pop() → 'C' (el último que entró) · c.desencolar() → 'A' (el primero que llegó)
    Para pensar shift() corre todos los elementos un lugar: con colas muy grandes es lento (O(n)). Por eso las colas “serias” usan un índice o una lista enlazada.

    #items es un campo privado de clase: nadie de afuera puede tocar el array y "colarse" en la fila.

    ¿Y dónde están en Expo Router?

    Una pila: el historial

    Cada Stack guarda sus pantallas en un array. La visible es el tope; “atrás” hace pop.

    Una cola: las acciones

    Cada router.push o toque en un Link se encola y se ejecuta en orden de llegada.

    El código de la derecha está sacado del paquete real (node_modules/expo-router, versión 57.0.20), solo se quitaron detalles. Vale la pena abrirlo en el editor con ellos.

    Si tocás dos links muy rápido, las dos acciones se procesan en el orden en que llegaron.

      _layout.tsx: el que decide cómo se muestra

      Un layout envuelve a todas las rutas de su carpeta y subcarpetas. Devuelve un navegador: Stack, Tabs, Drawer o un simple Slot.

      app/_layout.tsx Stack
      (tabs)/_layout.tsx Tabs
      productos/_layout.tsx Stack
      index.tsx[id].tsx

      El layout raíz también es el lugar para los providers globales: tema, sesión, gestos.

      Navegar con <Link>

      • Por defecto Link dibuja un <Text> tocable.
      • En web se convierte en un <a href> real: se puede abrir en otra pestaña.
      • Con asChild usás tu propio componente (un botón, una tarjeta).
      • Props de acción: push, replace, dismissTo, prefetch.
      Error real que te vas a cruzar Si el hijo de Link asChild recibe style={[a, b]}, Expo Router tira: “You are passing an array of styles to a child of <Slot>”. Solución: envolver el hijo en un componente propio.

      El error del array de estilos aparece solo en desarrollo y es muy común con Pressable. En la app de ejemplo lo resolvemos con TarjetaEjemplo e ItemProducto.

      Navegar con código: router

      ¿Link o router? Link cuando el usuario toca algo. router cuando navegás después de una lógica: guardar, validar, esperar una API.
      MétodoQué le hace a la pila
      push(href)Apila una pantalla nueva. Siempre.
      navigate(href)Apila, salvo que el destino sea la pantalla visible: ahí solo cambia sus params.
      replace(href)Cambia el tope por otra pantalla. La pila no crece.
      back()Pop: saca el tope.
      dismiss(n)Saca n pantallas de una vez.
      dismissTo(href)Desapila hasta encontrar esa ruta.
      dismissAll()Vuelve a la primera pantalla de la pila.
      canGoBack()¿Hay algo debajo? Devuelve true o false.
      setParams({...})Cambia los params de la pantalla actual.

      La diferencia push/navigate confunde mucho. Mostrarla en el simulador de la próxima diapositiva y en la pantalla "Pila de navegación" de la app.

      Stack: pantallas apiladas

      • Header con título y flecha atrás, automático.
      • Gesto de volver y animaciones nativas (usa react-native-screens).
      • screenOptions aplica a todas; Stack.Screen configura una.
      • presentation: 'card' (normal), 'modal', 'formSheet', 'transparentModal'…

      No hace falta declarar todas las pantallas en el Stack: las que no están se agregan solas. Se declaran para darles opciones.

      Tabs: secciones con pestañas

      • Cada archivo o carpeta dentro de (tabs) es una pestaña.
      • El grupo (tabs) no aparece en la URL: la pestaña Perfil es /perfil.
      • tabBarIcon, tabBarBadge, title se configuran por pestaña.
      Cambió en SDK 57 Importar Tabs desde 'expo-router' está deprecado. Usá 'expo-router/js-tabs'.
      Alternativa NativeTabs (desde 'expo-router/unstable-native-tabs') usa la barra nativa del sistema. Todavía es experimental.

      La app de ejemplo usa js-tabs porque funciona igual en Android, iOS y web, y permite íconos de @expo/vector-icons.

      Las tabs no apilan: cada una tiene su pila

      Cambiar de pestaña no agrega pantallas: solo cambia cuál se ve. Pero adentro de una pestaña puede haber un Stack con su propio historial. Probalo:

      › Tab activa: Productos

      Hacer push en Productos, cambiar a Inicio y volver: el detalle sigue ahí. Es lo que pasa en Instagram o en la app del banco.

      Drawer: el menú lateral

      • Se abre con el ícono ☰ o deslizando desde el borde.
      • Como las tabs, no apila: cambia la sección visible.
      • Sirve cuando hay muchas secciones que no entran en una barra de pestañas.
      • Necesita react-native-gesture-handler y react-native-reanimated (ya vienen en Expo Go).

      En SDK 57 el Drawer ya viene dentro de expo-router: no hace falta instalar @react-navigation/drawer.

      Rutas dinámicas [id]

      Los params siempre son texto En /productos/7, id vale "7", no 7. Si necesitás un número: Number(id).
      rutasipf:/

      Escribir URLs a mano con la clase. Probar /productos/mate: la ruta coincide aunque el producto no exista. Validar el dato es trabajo nuestro.

      Catch-all [...slug]

      URLslug
      /docs/guia['guia']
      /docs/guia/rutas['guia', 'rutas']
      /docs/a/b/c/d['a', 'b', 'c', 'd']
      ¿Cuándo usarlo? Rutas de profundidad variable: carpetas, categorías anidadas, documentación, un blog con fechas.

      Para darle una pantalla propia a /docs, agregá docs/index.tsx al lado del catch-all: las rutas más específicas tienen prioridad.

      Parámetros de búsqueda ?q=

      rutasipf://scheme buscarruta ?  q=mateparam &  categoria=bebidasparam
      • No hacen falta corchetes: buscar.tsx acepta cualquier ?clave=valor.
      • Se leen con el mismo hook: useLocalSearchParams().
      • router.setParams() los cambia sin apilar pantallas.
      • Como el estado vive en la URL, la búsqueda se puede compartir con un link.

      Params de ruta ([id]) vs params de búsqueda (?q=): los dos llegan en el mismo objeto.

      ¿Dónde estoy? Los hooks

      Valores reales estando en /productos/3 de la app de ejemplo:

      HookDevuelvePara qué
      usePathname()"/productos/3"La URL actual, sin params de búsqueda.
      useSegments()["(tabs)", "productos", "[id]"]Las partes del archivo; incluye los grupos.
      useLocalSearchParams(){ id: "3" }Params de esta pantalla. Opción por defecto.
      useGlobalSearchParams(){ id: "3" }Params de la URL global; se actualiza aunque la pantalla no esté visible.
      useNavigation()objeto navigationAcceso al navegador: getState(), setOptions(), eventos.
      useFocusEffect(cb)—Ejecuta código cada vez que la pantalla gana foco.
      Local vs global Una pantalla que quedó abajo en la pila no se vuelve a renderizar con useLocalSearchParams cuando cambia la URL de arriba. Con useGlobalSearchParams sí: más renders de los necesarios.

      En la app, cada ejemplo tiene al final el recuadro "¿Dónde estoy?" con estos hooks en vivo.

      Redirigir: <Redirect>

      • <Redirect> navega apenas se renderiza.
      • Reemplaza la ruta actual: la pantalla vieja no queda en el historial.
      • Equivale a router.replace(), pero escrito como componente.
      ¿Por qué replace y no push? Con push, al tocar “atrás” el usuario volvería a la ruta que redirige… y lo redirigiría de nuevo. Un bucle.

      La redirección condicional funciona, pero para proteger varias pantallas existe algo mejor: Stack.Protected.

      Rutas protegidas: Stack.Protected

      Pantallas registradas en el Stack
      • (tabs) siempre
      • privado guard={conSesion}
      • login guard={!conSesion}
      • Si guard es false, esas pantallas no existen para el navegador.
      • Cuando el guard cambia, las pantallas aparecen o desaparecen del historial solas.
      • Al iniciar sesión, el modal de login se cierra sin llamar a router.back().

      Probarlo en la app: pestaña Perfil → Iniciar sesión. Después, desde /privado, cerrar sesión y ver cómo desaparece la pantalla.

      En desarrollo, navegar a una ruta protegida con guard en false muestra un aviso "was not handled by any navigator".

      Deep links: abrir la app en una pantalla

      Como cada pantalla tiene URL, se puede abrir directo desde un link, un QR o una notificación. Expo Router lo resuelve solo.

      DóndeURL para abrir el producto 3
      App instalada (build propia)rutasipf://productos/3
      Expo Go en desarrolloexp://192.168.0.10:8081/--/productos/3
      Webhttp://localhost:8081/productos/3

      En Expo Go la parte "/--/" separa la dirección del servidor de la ruta de la app. El scheme propio (rutasipf://) solo funciona en una build de desarrollo o de producción.

      Errores comunes (y cómo salir)

      Comparar el id con un número

      id === 3 nunca es verdadero: los params son texto. Usá Number(id) o compará con '3'.

      Array de estilos en Link asChild

      You are passing an array of styles to a child of <Slot>

      Envolvé el hijo en un componente propio que arme su estilo adentro.

      Usar push después del login

      El usuario vuelve al login con “atrás”. Usá replace o Stack.Protected.

      Navegar a una ruta protegida

      The action 'NAVIGATE' … was not handled by any navigator

      Con el guard en false la pantalla no existe. Mostrá el botón solo si hay sesión.

      Versiones que no coinciden

      Instalar con npm install paquete puede traer una versión que Expo Go no tiene. Usá npx expo install.

      Poner cosas que no son rutas en app/

      Un Boton.tsx dentro de src/app se vuelve la ruta /Boton. Movelo a src/components.

      Para llevarse

      • Un archivo en src/app es una ruta. Los _layout deciden cómo se muestran.
      • Stack = pila (LIFO). push apila, back desapila, replace cambia el tope.
      • Tabs y Drawer no apilan: cambian de sección, y cada sección puede tener su pila.
      • [id] captura un segmento, [...slug] varios. Los params siempre son texto.
      • Stack.Protected hace que las pantallas existan solo cuando corresponde.
      • Las acciones de navegación forman una cola (FIFO) y se procesan en orden.
